## 如何运行

**在线直接玩**：<https://red-alert-web-game.app.workbuddy.host/>
（静态托管，无需任何安装，手机浏览器也能打开。）

想在本地跑，见下。

**必须用本地服务器打开，不能双击 `index.html`。**
游戏用的是原生 ES6 模块（`<script type="module">`），浏览器会以 CORS 策略
拦截 `file://` 协议下的模块加载——双击打开只会得到一片空白，控制台报
`Access to script at 'file:///...' has been blocked by CORS policy`。

```bash
# 本仓库自带（推荐，已禁用缓存，避免了改完代码刷新还是旧模块）
python3 serve.py            # 打开 http://localhost:8123

# 或者用任意静态服务器
python3 -m http.server 8000
npx http-server
php -S localhost:8000
```

然后访问 `http://localhost:8123`。

> 为什么自带服务器要禁缓存：普通 `http.server` 会按 `Last-Modified` 缓存 `.js`，
> 改完代码按 F5 常常还是旧模块，表现为「改了没生效」。

## 游戏操作

### 基本控制
- **左键点击**：选择单位或建筑
- **左键拖拽**：框选多个单位
- **Shift+左键**：加选/减选单位
- **右键点击**：移动单位或攻击目标
- **Ctrl+滚轮**：缩放视角
- **滚轮/Shift+滚轮**：滚动地图
- **空格键**：暂停/继续游戏
- **Delete 键**：删除选中的单位
- **F5**：保存游戏
- **F9**：加载游戏

### 自动交战（红警2 行为）

所有有攻击力的单位与防御建筑，只要敌人进入射程就**自动开火**，无需下达任何攻击命令。
移动途中同样会边走边打；追击某个目标时，若半路有别的敌人进入射程也会顺手还击。

- 玩家单位**不会**自动追出射程，以免擅自脱离你下达的移动命令；敌方 AI 会追击。
- 工程师、间谍等无攻击力的单位不参与交战；采矿车专注采矿，不参与自动交战。

### 建筑通行规则

**己方建筑不阻挡己方单位的移动**——基地建得再密，人员和战车也能直接穿行自家厂房，
不会被自己的建筑围死。敌方建筑仍然阻挡通行。
新单位的出厂落点依旧只会选空地，不会把单位生成在建筑里。

### 单位命令
- **S 键**：停止当前命令
- **A 键**：攻击移动（移动并自动攻击沿途敌人）
- **G 键**：守卫当前位置
- **Ctrl+A**：全选己方单位
- **Ctrl+数字 1-9**：建立编队
- **数字 1-9**：召回编队（双击跳转视角）
- **Home 键**：回到主基地视角

### 资源管理
- 采矿车会自动采集黄色矿石
- 矿石会自动运回矿场转化为资金
- 资金用于建造建筑和生产单位

### 建筑系统
- **建造厂**：基地核心，提供50电力
- **发电厂**：提供200电力
- **矿厂**：精炼矿石，附赠采矿车
- **兵营**：训练步兵单位
- **战车工厂**：制造车辆单位
- **雷达站**：解锁小地图视图
- **科技中心**：解锁高级科技单位
- **维修站**：附近车辆自动维修

### 防御建筑
- **城墙**：廉价障碍物
- **碉堡**：快速射击步兵防御
- **重炮塔**：反装甲重炮
- **防空炮**：快速射击火力
- **特斯拉线圈**：强力电磁攻击（需科技中心）

### 阵营

玩家固定为**盟军**，敌方固定为**苏联**。建造面板只列出本阵营与通用单位，
敌方阵营单位不再出现（此前 `canBuild` 不检查阵营，盟军能造出天启坦克）。

### 单位特性（红警2 设定）

- **光棱塔**：相邻光棱塔会把光束聚焦到同一目标，每多一座 +50% 伤害
- **磁暴线圈**：耗电极大，基地电力不足时无法开火
- **天启坦克**：双炮管齐射
- **谭雅**：携带 C4，对建筑造成毁灭性伤害，可单兵拆家
- **军犬**：扑咬步兵一击必杀
- **间谍**：潜入敌方建筑触发效果后消失 —— 电厂使其断电 15 秒，兵营/车厂让己方部队晋升老兵，其余窃取资金
- **维修站**：范围内地面车辆持续恢复（约 60HP/s）

### 装甲与伤害类型

每个单位/建筑都有**装甲类型**，每种武器都有**伤害类型**，命中时按矩阵取倍率。
这不是装饰表——`Entity.calculateDamage` 真的会查它：

| 伤害类型 \ 装甲 | 无甲 | 轻甲 | 中甲 | 重甲 | 混凝土 | 钢铁 |
|---|---|---|---|---|---|---|
| 子弹 | 100% | 100% | 70% | 40% | 20% | 10% |
| 炮弹 | 100% | 120% | 100% | 80% | 60% | 40% |
| 火箭 | 80% | 80% | 100% | 100% | 80% | 60% |
| 导弹 | 100% | 100% | 100% | 100% | 100% | 80% |
| 激光 | 100% | 100% | 100% | 80% | 60% | 50% |
| 电击 | 100% | 100% | 90% | 90% | 50% | 30% |
| 炸弹 | 100% | 100% | 100% | 100% | 120% | 100% |
| 鱼雷 | 0 | 0 | 0 | 0 | 0 | 0（对舰船 150%） |

实际手感举例：同样是 100 点面板伤害，步枪打步兵是全额的 100，打灰熊坦克（中甲）只剩 70，
打混凝土建筑只剩 20；而炸弹砸混凝土建筑有 120% 加成。鱼雷打陆地目标恒为 0。

具体每件武器的伤害类型写在 `definitions.js` 的 `DAMAGE_BY_TYPE`，
每种单位的装甲写在 `ARMOR_BY_TYPE`（未列出的按兵种大类取 `DEFAULT_ARMOR_BY_CATEGORY` 兜底）。

### 超级武器

四种超级武器（核弹 / 闪电风暴 / 铁幕装置 / 超时空传送）冷却统一为 **90 秒**。
发射井、天气控制器等建筑建成后才开始充能；**建筑被摧毁，对应超武立即注销**，
不会留下一个永远倒计时的空条目。

### 常见问题

**造不出兵了怎么办？** 先看顶栏人口显示（`已用/60`）。满员时生产会暂停而不是卡死，
腾出空位后自动继续。点建造项若不可建造，条目上会直接写明原因（缺什么科技、电力还是资金），
点击也会弹出提示。

**新造出来的兵为什么不动？** 出厂单位会自动前往集结点并在原地守卫；
选中生产建筑后右键地图可以设置集结点。守卫状态下单位会自动反击射程内敌人，
追出一定距离后归位。

### 胜利条件
- 摧毁敌方建造厂即获胜
- 如果你的建造厂被摧毁则失败

## 技术实现

- HTML5 Canvas 渲染
- 原生 ES6 模块（20 个模块，无构建工具，直接开 `index.html` 即可运行）
- A* 寻路（索引二叉堆 + generation 时间戳复用工作数组，全程零对象分配）
- 均匀网格空间索引（SpatialGrid），覆盖点选/框选/射程/溅射四条查询路径
- 静态地形连通区域预计算，避免不可达目标上空跑迭代
- 战争迷雾（增量降级 + dirty 标记 + 1px/格离屏画布）
- 游戏循环、状态管理、AI 行为系统、Web Audio API 音效

## 测试

仓库外的测试工程（`red-alert-tests/`）用 Node 直接驱动真实游戏循环：
桩掉 `window`/`document`/`localStorage`/`navigator`，手动接管 `requestAnimationFrame`，
因此跑的是**同一份生产代码**，不是模拟实现。

```bash
node smoke.mjs        # 8 项   —— 能否加载、能否跑帧
node correctness.mjs  # 28 项  —— 正确性 Bug 回归（含间谍渗透 7 项）
node armor.mjs        # 40 项  —— 装甲/伤害矩阵
node sim.mjs          # 13 项  —— 1400 帧压力模拟
node modules.mjs      # 19 项  —— 模块接口与回调适配器
```

两个关键方法：

- **固定随机种子**：地图生成用了 `Math.random`，不固定种子时同一段模拟每次结果都不同，
  测试会随机红绿。`harness.mjs` 用 mulberry32 替换掉它。
- **反向证明**：每条断言都要能把对应的修复「改回旧逻辑后跑红」。只验证「改了之后是绿的」
  无法区分「修好了」和「断言写空了」——本轮就有 2 条断言最初是空转的，靠反向证明才发现。

## 性能优化记录

### 第六轮（本轮）：地形预渲染 + 距离计算去 hypot

基准脚本 `bench_round6.mjs`，方法论同第五轮（同进程交错 A/B、多轮取中位数）。

| 优化项 | 改动前 | 改动后 | 结论 |
|---|---|---|---|
| ORE/WATER 地形绘制（全图 5184 格扫描） | 34449 次 canvas 调用 | 5519 次 | **降 84%，保留** |
| 抛射物推进 updateProjectiles（200 弹） | 15.99 ms | 6.00 ms | **2.67x，保留** |
| 单位移动 moveUnit | 1.46 ms | 1.20 ms | **1.22x，保留** |
| 射程查询内部距离判定 | 1.88 ms | 1.94 ms | ±3% 噪声带内，语义更明确，保留 |

- **地形预渲染**：ORE（矿石晶体）与 WATER（水面波纹）此前不走图块缓存，每格每帧程序化
  绘制——ORE 每格约 14 次 canvas 调用（6 个双层菱形）+ 1 次 sin，WATER 每格 5 次 + 2 次 sin。
  实测最重视口中这两类地形占 28.9%（501/1734 格），每帧产生约 4000 次多余调用。
  现改为预渲染：WATER 按相位量化 64 档（phase 含 tx/ty 项，逐格天然错相；64 档/2.6s 周期
  ≈ 25 步/秒，慢波纹跳变不可辨）；ORE 晶体按「晶体数 × variant」预渲染 24 张透明底图层，
  呼吸脉冲改用渲染时的 `globalAlpha` 缩放实现。每格降为 1~2 次 drawImage。
  收益在浏览器侧（canvas API 调用开销），stub 环境以调用次数为代理指标。
- **Math.hypot 消除**：hypot 是防溢出实现，实测比 `sqrt(dx²+dy²)` 慢约 7 倍；游戏坐标
  最大 2304px，平方和远低于 double 溢出阈值，防溢出是纯浪费。全部 25 处按场景替换：
  只比远近的用平方比较（连 sqrt 都省），需要真实距离做归一化/falloff 的用 sqrt。
  射程查询内部的 ±3% 差异在测量噪声带内（该路径瓶颈是格子遍历而非距离函数），
  保留平方写法是语义选择而非性能声明。
- **间谍渗透接空间索引**：原先每个间谍每帧全实体扫描（O(n)/帧），改为
  `forEachInRange`（零分配 + 命中即终止），半径 +3 格覆盖大建筑中心偏移。
  由 correctness.mjs ⑧ 组 7 项用例守着（含 size 3 跨格建筑命中、超距不误判），
  反向证明：渗透路径整体失效时 8a/8c 变红。

### 第五轮：结构拆分 + 渲染热点

基准方式为**同进程交错 A/B**（每轮交换新旧实现的执行顺序，各跑 5 轮取中位数）——
先跑旧再跑新会被 JIT 预热干扰，单看一组数字会得出相反结论。

| 优化项 | 改动前 | 改动后 | 结论 |
|---|---|---|---|
| 地形图块取用（5184 格全图） | 0.31 ms | 0.05 ms | **5.74x，保留** |
| 视口剔除（抛射物/爆炸/飘字） | — | 跳过 144/200 抛射物 | **保留** |
| 消除射程查询的数组分配 | 7.47 ms | 8.06 ms | 慢 1.08x，**已回退** |
| 实体 y 序排序复用缓冲区 | 15.63 ms | 15.87 ms | 慢 1.02x，**已回退** |

- **地形图块缓存**：`tileCache` 原先用字符串 key（`x + ',' + y`），每帧要为上千格拼接字符串
  并做哈希；改为二维数组按 `[ty][tx]` 直接索引后消失了这部分开销。折算到单帧约 14 µs，
  占 16.7 ms 帧预算的 0.09%。
- **视口剔除**：抛射物按线段包围盒、爆炸与飘字按圆包围盒判断是否落在可视区内，
  视口外直接跳过绘制。本仓库的基准环境里 canvas 是桩，绘制是空操作，所以测不出耗时差异，
  收益要到浏览器里才体现——这里只列出被跳过的对象数量作为上界。
- **两个「想当然的优化」被否掉了**：给射程查询加对象池环形缓冲区、给实体排序复用数组，
  直觉上都在省分配，实测反而更慢。原因是这两处本来就不是热点（射程查询占单帧预算 0.5%），
  而环形缓冲引入了额外的下标运算与脏检查。代码里已留注释，避免以后有人再优化一遍。

### 第四轮：寻路与空间索引

| 优化项 | 改动前 | 改动后 | 提升 |
|---|---|---|---|
| A* 寻路 2000 次 | 610 ms | 185 ms | 3.9x |
| 溅射候选查询 2000 次 | 35 ms | 8 ms | 4.2x |
| 框选查询 2000 次 | 11 ms | 3 ms | 3.9x |
| 采矿车找精炼厂 3000 次 | 5.8 ms | 0.7 ms | 7.9x |

关键改动：

1. **寻路零分配**：A* 的开放集从「对象二叉堆」改为「索引二叉堆」（`Int32Array` 存节点索引 +
   `Float32Array` 存 f 值），消除每次寻路上万次的临时对象分配；邻居偏移表与工作数组提到模块级/实例级复用。
2. **静态连通性预检**：目标不可达时 A* 会空跑满 3000 次迭代上限，实测占总迭代量的 79%。
   地图生成/读档时预计算地形连通区域，分属不同区域则压缩迭代上限，用少量「尽量接近目标」的精度换掉卡顿。
3. **每帧寻路预算**：单帧最多 6 次寻路 / 9000 次节点扩展，超额调用自动降级到保底迭代数，
   避免玩家一次性给几十个单位下令时同帧集中计算造成的掉帧尖峰。
4. **空间索引补齐**：此前 SpatialGrid 只服务于 1 个查询，点选、框选、溅射、找精炼厂仍是全量 O(n)。
   现已全部接入，并修复跨格大建筑重复返回导致溅射伤害被重复结算的问题。
5. **精炼厂缓存**：采矿车每帧都要找最近精炼厂，原先每车遍历全部实体；改为随实体增删失效的缓存。

## 本轮修复的正确性问题

这些都是「玩起来会真的坏掉」但不会报错的问题，逐条有回归测试守着：

| # | 现象 | 根因 |
|---|---|---|
| ① | 超级武器 10 秒就能再放一次 | `cooldown: 600` 是帧数（10 秒），注释却写着「10 分钟」；单位混乱导致玩家几乎无法反制。现统一为 `cooldownSec: 90`，由 `FPS` 换算 |
| ② | 读档后在建的建筑可以被人穿过、也能被叠着再建一座 | 存档恢复占用格时写了 `&& e.built`，没完工的建筑不进占用表 |
| ③ | 读档后刚出厂的兵僵在原地不动 | `autoGuard` 不在存档白名单里；且触发条件要求 `path.length > 0`，而 `path` 不存档，读档后永远不满足 |
| ④ | 发射井被拆了，核弹还在倒计时、还能放 | 超武只在建筑建成时注册，没有任何注销路径 |
| ⑤ | 工程师被右键点到自己满血建筑上后彻底卡死，不再响应任何命令 | 该分支没清 `attackTarget`，而路径无解时又没有兜底 |
| ⑥ | 玩家单位打不到敌方在建的建筑，但溅射伤害却能打到 | `getEnemiesInRange` 多过滤了一个 `e.built`，与 `applySplashDamage` 判定不一致 |
| ⑦ | 读档后所有鼠标操作作用在旧世界上（点选、框选全失效） | 读档会 new 出全新 `GameState` 与 camera，输入层缓存的还是旧引用 |

⑦ 的验证方式值得一提：把 `input.rebind(...)` 注释掉后测试立刻变红
（`input._gameState` 仍指向读档前的旧世界），确认断言不是空转的。
